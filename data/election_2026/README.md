# 2026 美国中期选举新闻数据集

本数据集仅围绕 2026 年 11 月美国中期选举及选后反应，原始网页的发布日期
限制为 **2026-11-03 至 2026-11-16**。不使用其他年份选举或其他主题补齐数量。
实际来源、采集时间、文档类型和清洗方式以 `sources.json` 为准。

## 从网盘获取最终数据集

最终 1,000 篇正文以 `election_2026_1000.zip` 单独通过网盘分发，不上传 Git。
下载地址：[Google Drive 数据集文件夹](https://drive.google.com/drive/folders/12gJchd3Gv5oO9GsbdZrfX5CRR0VNfaGZ)。
从文件夹下载 `election_2026_1000.zip`，详见 [DOWNLOAD.md](DOWNLOAD.md)。下载后在项目根目录执行：

```bash
python3 scripts/dataset_archive.py import --archive /path/to/election_2026_1000.zip
```

将示例路径替换为实际下载路径。脚本校验全部正文的 SHA-256，并从同一份 1,000 篇
快照恢复 `scale_10`、`scale_100`、`scale_1000` 和 `real_20`，与已完成实验的输入一致。
使用数据集无需重新采集网页或生成变体。维护者运行
`python3 scripts/dataset_archive.py pack` 可生成待上传的
`exports/election_2026_1000.zip` 及校验文件；`exports/` 已被 Git 忽略。

## 数据组成

从公开网页获取了 **211 条去重后的真实新闻文本**：44 篇独立文章和 167 条
带独立锚点链接及发布时间的实时报道条目。来源包括 CBS News、The Guardian、
AP 的 ap.org 网站和 Roll Call；CBS 占绝大多数，不能将本数据集视为媒体均衡样本。
其中 210 条至少有四个可用于改编的句子单元，选择 200 条构建规模集。

| 文件夹（`corpora/` 下） | 文档数 | 原始文本 | 人工变体 | 用途 |
|---|---:|---:|---:|---|
| `real_20` | 20 | 20 篇独立文章 | 0 | 检查真实新闻的文本相似性 |
| `scale_10` | 10 | 2 | 8 | 小规模受控功能验证 |
| `scale_100` | 100 | 20 | 80 | 后续规模实验 |
| `scale_1000` | 1,000 | 200 | 800 | 后续规模实验 |

`scale_1000` 的 200 条原文包含 44 篇独立文章及 156 条实时报道条目。
**这不是 1,000 篇独立采集的新闻，而是基于 200 条真实文本构建的合成扩充数据集。**
实时报道条目有各自的标题、时间和链接，但同一页面中的条目并非独立媒体来源。

`scale_10 ⊂ scale_100 ⊂ scale_1000`。每一规模都包含完整的来源组，每组一篇原文、
四篇变体，所以人工变体比例固定为 80%，来源组最大大小固定为 5。
它们是嵌套的规模实验集，不是训练集/测试集；不能用于宣称无数据泄漏的泛化测试。
`real_20` 与规模集也有原文重叠。

## 目录和记录

- `originals/`：清洗后的真实正文，UTF-8 `.txt`，不含额外标题和数据集标识。
- `raw/`：网页 HTML 和 HTTP 状态、最终 URL、实际获取时间等缓存。
- `corpora/`：四个可直接交给项目读取函数的语料文件夹。
- `sources.json`：全部真实文本的来源、发布时间、作者、提取方式、哈希及文件路径。
- `collection_audit.json`：65 个候选网页的采集情况，包括拒绝、日期不符、过短和重复等原因。
- `manifests/*.json`：各语料集的逐文档清单、来源组、父文档、修改操作、字数、shingle 数及校验和。
- `within_family_labels.json`：200 个来源组内的全部 2,000 对文档的精确 Jaccard 和阈值标签。
- `dataset_summary.json`：实际组成、长度分布、去重检查及使用限制。
- `build_archive/`：本次调整抽样顺序前的本地构建快照，非正式实验输入。

这里的 `.txt` 正文、人工变体及网盘分发包已加入 `.gitignore`，通过网盘与代码分开提供。
来源清单、构建及导入脚本、统计与标签可随代码版本控制。原始报道版权仍归各发布者，
来源署名保留在数据包中的元数据里。

## 采集与清洗

采集入口及跟进规则记录在 `scripts/collect_election_news.py` 中。主要从网页提供的
JSON-LD `articleBody` 抽取全文；少数发布者使用经检查的正文 HTML 容器。
不把搜索摘要或模型转述当作新闻原文。不绕过访问拒绝、验证码或显式付费限制。

清洗移除 HTML、图片/图注容器、脚本以及独立的阅读全文提示，并保留正文段落。
标题、URL、作者等信息放在元数据中，避免来源信息制造虚假的文本相似度。
每条真实文本至少 80 个空白分隔词，且必须在日期范围内并包含选举相关词。
按清洗后规范化正文去除完全重复文本；自然发生的部分转载/相似文本不自动删除。
这里的自动主题筛选不是人工逐句事实核查。

采集程序只处理实际下载到的内容。部分网页 HTTP 200 但内容为访问检查页，
也不作为文章接收。所有失败和排除情况保留在采集审计中。

## 人工改编方式

对每条选定原文生成四个不同版本，操作仅为相邻句子单元调换、删去部分句子单元。
不通过随机追加编号、替换候选人姓名、修改选举数字或虚构事实来制造差异。
句子单元由标点和段落边界启发式切分，因此这些是**机械编辑实验文本**，不能当作
经过记者审核的新闻；删除上下文和调整顺序仍可能影响阅读与语义。

四个版本分别从候选编辑中选择最接近 0.97、0.90、0.81、0.65 Jaccard 的文本。
这些数值仅是选取目标，不保证每篇都能达到；最终数值及标签都重新计算。
所有比较使用当前 `Shingling(k=10)` 的规范化和整数哈希集合。

- `kind=real`：从真实网页提取的正文。
- `kind=synthetic_variant`：人工变体；其 `published_at` 为 null，原文时间另存。
- `parent_id` / `family_id`：对应原文，可追溯整个来源组。
- `change`：句子顺序、删除的句子序号、目标值与实际 Jaccard。

**同组不等于相似。** 精确 Jaccard ≥ 0.8 才标为相似；较大删改可能低于阈值。
`within_family_labels.json` 只穷举同组文档对。跨组文档对是“未标注”，绝不能默认视为
不相似；需要评价全库召回率时，必须另算全库精确 Jaccard 基准。

## 抽样与扩展性限制

先按发布者、文章类型和长度分层选取来源，再调整来源组排列，使嵌套前缀的
平均字数、shingle 数与总体尽量接近。随机种子为 `20261116`，不是按 MinHash/LSH
检测成功与否挑选语料。实际长度统计保存在 `dataset_summary.json`，小样本不可能
完全复制大样本分布。

固定每组 5 篇可以避免人为制造单组数百篇的重复簇，但真实文章跨组的内容重叠
仍可能形成更大的 LSH 桶。后续应同时报告文档总数、总字数/总 shingles、候选数
和重复结构。10/100/1,000 的耗时对比现已由单独的基准程序完成，见项目根目录
`SCALABILITY_REPORT.md` 和 `results/scalability/`。这些数据不代表一般新闻库的性能。

本次构建的实际统计如下（不是运行时间比较）：

| 规模集 | 平均词数 | 平均独特 shingles（k=10） |
|---|---:|---:|
| 10 | 247.0 | 1,310.1 |
| 100 | 239.0 | 1,307.07 |
| 1,000 | 243.225 | 1,325.505 |

平均值接近不表示完整分布相同；特别是 1,000 篇中有更长的尾部文章。
来源清单实际发布日期为 2026-11-03 至 2026-11-08，均在允许的事件日期窗口内。

## 本次校验结果

- 四个目录的文件数与清单一致；SHA-256、字数、shingle 数、来源关联、嵌套关系通过校验。
- 1,000 篇中规范化后完全重复的文本数量为 0。
- 2,000 个组内文档对中，871 对的精确 Jaccard ≥ 0.8，1,129 对低于阈值。
- `real_20` 的 190 对全量比较中，0 对达到 0.8，LSH 返回 0 个候选。
- `scale_10` 的 45 对全量比较中，9 对达到 0.8，LSH 返回 12 个候选，
  候选精确率 0.75，召回率 1.0（k=10、120 维、seed=42、12 bands × 10 rows）。

真实 20 篇中没有正例，因此程序显示的 precision/recall=1.0 是空集合处理约定，
不是“真实新闻检测达到完美效果”的证据。小规模结果仅验证功能，不代替大规模质量评价。
保存的对比结果位于项目 `results/election_real_20_analysis.json` 和
`results/election_scale_10_analysis.json`。

## 在 PyCharm 中使用

`main.py` 已默认读取 `corpora/real_20`。运行后看到的是实采新闻的结果，不再是
旧的十篇生成稿。如果没有达到 0.8 的文档对，这是合理结果：主题一致不保证文本近重复。

需要观察受控改编的检测效果时，将 `main.py` 中目录末尾的 `real_20` 改为 `scale_10`。
不要直接把当前全量评价流程用于 1,000 篇的 LSH 加速计时；它会额外计算所有文档对。

## 校验已导入的数据集

```bash
python3 scripts/build_election_dataset.py --verify-only
python3 main.py
```

校验模式只检查已导入的文件和标签，不重新构建，也不需要原始 HTML 缓存。

## 可选：从网页重新采集和构建

以下为数据集制作过程，仅供维护者追溯；复现实验优先使用网盘中的固定快照。

在项目根目录执行：

```bash
python3 -m pip install -r requirements-data.txt
python3 scripts/collect_election_news.py --max-pages 65
python3 scripts/build_election_dataset.py
python3 scripts/build_election_dataset.py --verify-only
python3 main.py
```

采集需要联网和系统 `curl`。已有 HTML 缓存会直接复用；同一份缓存与相同代码会
产生相同的选择与改编结果。网页将来更新、失效或被限制访问时，新下载无法保证
与此次快照完全相同，可用来源 SHA-256 校验差异。

构建遇到语料目录中不属于本次选择的旧文件会停止，避免把新旧数据混合。
如需更换构建配置，先把旧 `corpora` 文件夹移到本地备份，再重新构建。
校验命令检查文件数量、SHA-256、正文去重、原文关联、嵌套关系及所有组内标签。

旧 `data/news_corpus`、`data/sources.json`、`results/analysis.json` 和旧报告中的数字
仍然属于之前的生成稿演示，未混入本次数据集。
